# Core Runtime Engines: Ag2RuntimeEngine Analysis

This document identifies and extracts the fundamental runtime engines powering the Ag2RuntimeEngine framework. These engines are responsible for the orchestration of autonomous agents, state management across conversational turns, and the execution of code within isolated environments.

---

## Engine 1: Orchestration Runtime Engine

### What it does
The Orchestration Runtime Engine serves as the primary coordination layer for multi-agent workflows. It manages the message passing protocol between agents, handles the termination conditions of a conversation, and maintains the global state of the dialogue history. 

It functions by:
1. **Input:** Accepting a sequence of messages and an agent registry.
2. **State Lifecycle:** Initializing the conversation context, processing sequential or parallel agent turns, and appending updates to the shared memory buffer.
3. **Invariant Preservation:** Ensures that message schema integrity is maintained and that sender/recipient addressing remains consistent throughout the session.
4. **Output:** A serialized object representing the final state of the conversation and the cumulative message history.

### Implementation Code
```typescript
interface Message {
  role: 'user' | 'assistant' | 'system';
  content: string;
  name?: string;
}

interface Agent {
  name: string;
  process: (messages: Message[]) => Promise<Message>;
}

class OrchestrationRuntimeEngine {
  private history: Message[] = [];
  private agents: Map<string, Agent> = new Map();

  public registerAgent(agent: Agent): void {
    this.agents.set(agent.name, agent);
  }

  public async executeTurn(senderName: string, recipientName: string, content: string): Promise<Message> {
    const message: Message = { role: 'assistant', content, name: senderName };
    this.history.push(message);

    const recipient = this.agents.get(recipientName);
    if (!recipient) throw new Error(`Agent ${recipientName} not found.`);

    const response = await recipient.process(this.history);
    this.history.push(response);
    return response;
  }

  public getHistory(): Message[] {
    return [...this.history];
  }
}
```

## Engine 2: Sandbox Execution Runtime Engine

### What it does
The Sandbox Execution Runtime Engine is designed for the safe, isolated execution of code generated by agents. It acts as a middleware between the generated code and the host system, ensuring that malicious or unstable operations are contained.

It functions by:
1. **Input:** Raw source code strings and execution environment configuration.
2. **State Lifecycle:** Creating an ephemeral process context, monitoring resource consumption (CPU/Memory), and streaming output logs.
3. **Invariant Preservation:** Enforces timeout limits and prevents unauthorized access to host file system resources.
4. **Output:** A standardized result object containing stdout, stderr, and the final exit status code.

## Engine 3: State Persistence Runtime Engine

### What it does
The State Persistence Runtime Engine manages the long-term memory of the Ag2RuntimeEngine. It ensures that agent configurations, conversation histories, and persistent state variables can be serialized and recovered across process restarts.

It functions by:
1. **Input:** Current state snapshots and persistence layer drivers (e.g., FileSystem, KV Stores).
2. **State Lifecycle:** Generating checksums for state integrity, performing atomic write operations, and reloading the cache on cold starts.
3. **Invariant Preservation:** Guarantees atomicity to prevent data corruption during unexpected application termination.
4. **Output:** Boolean indicators of persistence success or fully hydrated application state objects.
