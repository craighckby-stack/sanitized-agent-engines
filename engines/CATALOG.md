## Clean-Room Isolation & Governance Specification

All engines harvested and registered within this catalog must satisfy the five-tier DARLEK CAAN verification criteria:

1. **Trade Name & Telemetry Sanitization**: Elimination of proprietary telemetry beacons, vendor-locked endpoints, and branded identifiers.
2. **Deterministic Sandboxing**: Tool execution and filesystem side-effects are restricted to virtualized in-memory abstractions (`VirtualFileSystem`) with strict path-traversal prevention.
3. **Bounded Context Budgets**: Enforcement of discrete token limits, context-window sliding strategies, and non-linear branch pruning to prevent runaway resource exhaustion.
4. **Resilient Loop Convergence**: Autonomous loops must enforce hard limits on iterations (`maxIterations`), step timeouts, and error escalation circuits.
5. **Universal Model Abstraction**: Communication interfaces adhere strictly to standardized OpenAI/Anthropic/Ollama delta streaming protocols without closed vendor hooks.

## Lifecycle Status Definitions

- **Indexed**: Ingestion stage; upstream AST parsed and clean-room specification generated.
- **Clean-Room Sanitized**: Proprietary telemetry removed; modular kernel and subsystem components decoupled.
- **Verification Complete**: Unit and property-based regression suites operational; token containment verified.
- **Production Sealed**: Cryptographically verified and marked immutable for mission-critical orchestration.

## Catalog Registration Protocol

When appending new autonomous engines to this catalog:
1. Ensure full specification compliance documented in `engines/<engine-name>/specification.md`.
2. Provide discrete decoupled implementations matching the 5-layer modular architecture (`01` through `05`).
3. Export consolidated engine runtime factory via `engines/<engine-name>/runtime.ts`.
4. Register the engine record in the Extracted Engines Directory table above with immutable SHA reference and date.
